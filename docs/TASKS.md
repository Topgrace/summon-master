## 현재 목표

스마트폰 가로 우선·태블릿/PC 지원 웹 시제품 구현 준비: 핵심 화면 검토, 미정 세부 동작 정리, 기술 선택·구현 계획 작성.

- 완료 조건: 필요한 제품 결정을 플레이 명세서에, 기술·실행 결정을 개발 명세서에 기록하고 구현 계획 검토를 마친다.
- 현재 상태: 명세 2개와 S03 소환 전·중·후를 보완한 [와이어프레임](../와이어프레임.png)이 존재한다. 와이어프레임 파일명은 고정하고 이전 확정본은 Git 이력으로 관리한다. 실행 코드·패키지 설정·테스트는 없다. [조작·연출 검토안](조작_연출_검토안.md)에 초안 대조 결과와 후속 보완 기록을 관리한다.
- T001·T002·T003·T013·T014·T015는 완료했다. T004의 P01은 두 번 탭으로, P09는 선택·취소·안내·중단/복원 규칙으로 승인·명세 반영했다. P09 문서 검증을 완료했으며, P02–P08 세부 제안은 결정 대기다. 엔진·프레임워크 선택과 구현은 미착수다.

## 재개 지점

- 마지막 완료: T015 모델·PC 독립 재개 절차 보완과 문서 검증.

- 결정 대기: T004의 스마트폰 기준 P02 화면·입력 시작값과 P03–P08 제작 제안. 기기 우선순위·P01·P09는 확정되어 재승인이 필요하지 않다.
- 다음 제품 작업: [검토안](조작_연출_검토안.md) 3.1절에 스마트폰 가로용 P02 화면 배분·글자·숫자·터치 영역·화면 맞춤 제안을 재구성한다. 기존 1280×720·영역 비율·버튼 크기는 미승인 제안이다. 검토 후 P03 무거움 체험 방식으로 이어간다.
- 구현 착수 조건: T004의 관련 제품 결정과 T005의 기술·구현 계획 검토 완료. 현재 기술 선택·패키지 설치·앱 구현은 미착수다.
- 검증 상태: 제품 문서 검증은 아래 검증 결과를 참조한다. 앱 실행·Q01–Q20·실제 기기·다른 모델에서의 재개 시험은 미실행이다.
- Git 전달: 아래 커밋 직전 스냅샷 참조. 실제 커밋 결과는 Git 이력에서 확인한다. 푸시는 사용자가 직접 수행하며 원격 전달 완료로 간주하지 않는다.

## Git 인계 상태

아래는 이번 누적 변경을 커밋하기 직전의 스냅샷이다. 커밋 식별자 자체를 같은 커밋의 본문에 기록하지 않으며, 실제 결과는 `git log -1 --oneline`과 `git status --short --branch`로 확인한다. 새 세션에서는 실제 Git 상태를 다시 확인하며, 이 표를 원격 최신 상태의 증거로 사용하지 않는다. 개인 PC의 작업 경로는 달라도 된다.

## 관리 규칙

- 상태는 `대기 / 진행 / 결정 대기 / 검증 대기 / 완료`로 표기한다. `대기`는 미착수, `결정 대기`는 제품·기술 결정이 필요한 상태다.
- 작업 ID는 `T001`부터 부여하고 유지한다. 게임 저장 체크포인트 `CP01` 등과 구분한다.
- 작업 시작 시 이 문서와 관련 명세를 읽는다. 의미 있는 단계 완료 시와 작업 종료 전에 상태·검증·결정 대기·재개 지점을 갱신한다.
- 완료 조건을 확인하고 검증 근거를 남긴 뒤 `완료`로 바꾼다. 코드 작성만 끝났으면 `검증 대기`로 둔다.
- 검증 기록에는 환경·절차·결과·미실행 범위를 남긴다. 자동 검사와 실제 기기 확인을 구분한다.
- 요구사항 본문은 복사하지 않고 기준 문서의 절·ID를 참조한다. 새로운 제품·기술 결정은 기준 문서에 먼저 기록한다.
- 미정 사항은 임의로 확정하지 않는다. 작업 목록 등록이나 완료 표시를 사용자 승인으로 간주하지 않는다.
- 커밋은 사용자의 명시적 지시가 있을 때 누적 변경사항을 모아 수행한다.
- 재개 지점과 Git 인계 상태는 위 한 곳을 갱신한다. 별도 세션별 인계 문서를 누적하지 않는다. 검증 결과 표에는 이력을 남기되, 현재 상태와 과거 상태를 구분한다.
