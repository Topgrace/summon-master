## 현재 목표

스마트폰 가로 우선·태블릿/PC 지원 웹 시제품 구현 준비: 핵심 화면 검토, 미정 세부 동작 정리, 기술 선택·구현 계획 작성.

- 완료 조건: 필요한 제품 결정을 플레이 명세서에, 기술·실행 결정을 개발 명세서에 기록하고 구현 계획 검토를 마친다.
- 현재 상태: 플레이 명세 v0.15·개발 명세·루트 와이어프레임 존재. 기존 P01–P09 승인 범위·자동 힌트 3/6/10초 유지. 효과음·배경음·소리 설정 검토는 핵심 기능 구현·검증 뒤로 이동. [T005 기술·구현 계획안](기술_구현_계획안.md) 작성, 기술 구성 승인 대기. 제품 앱·패키지·테스트는 없다.
- T001·T002·T003·T013·T014·T015 완료. T004는 음향 등 잔여 결정 대기, T005는 계획안 검토 단계. 지원 화면·초기 소리 버튼·기록 보관/접근 상세와 일부 연출 시간은 미정. 구현은 미착수다.

## 관리 규칙

- 상태는 `대기 / 진행 / 결정 대기 / 검증 대기 / 완료`로 표기한다. `대기`는 미착수, `결정 대기`는 제품·기술 결정이 필요한 상태다.
- 작업 ID는 `T001`부터 부여하고 유지한다. 게임 저장 체크포인트 `CP01` 등과 구분한다.
- 작업 시작 시 이 문서와 관련 명세를 읽는다. 의미 있는 단계 완료 시와 작업 종료 전에 상태·검증·결정 대기·재개 지점을 갱신한다.
- 완료 조건을 확인하고 검증 근거를 남긴 뒤 `완료`로 바꾼다. 코드 작성만 끝났으면 `검증 대기`로 둔다.
- 검증 기록에는 환경·절차·결과·미실행 범위를 남긴다. 자동 검사와 실제 기기 확인을 구분한다.
- 요구사항 본문은 복사하지 않고 기준 문서의 절·ID를 참조한다. 새로운 제품·기술 결정은 기준 문서에 먼저 기록한다.
- 미정 사항은 임의로 확정하지 않는다. 작업 목록 등록이나 완료 표시를 사용자 승인으로 간주하지 않는다.
- 커밋은 사용자의 명시적 지시가 있을 때 누적 변경사항을 모아 수행한다.
- 재개 지점과 Git 인계 상태는 위 한 곳을 갱신한다. 별도 세션별 인계 문서를 누적하지 않는다. 검증 결과 표에는 이력을 남기되, 현재 상태와 과거 상태를 구분한다.
