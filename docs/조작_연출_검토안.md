### 1.1 S03 후속 보완 — T013

- 사용자 요청에 따라 교실 소환술 배우기를 소환 전·중·후 3컷으로 추가했다. 위 표는 보완 전 초안의 검토 기록으로 유지한다.

- S03 추가 당시에는 선택 취소(P09) 등 미정 동작을 승인한 것으로 취급하지 않았다. P09는 이후 별도 사용자 승인으로 확정했으며 4절에 기록한다. 다른 장면의 상세 전/중/후 화면과 실제 사용성 검증은 별도 작업으로 남긴다.
- 개정본 A–G를 직접 확인했다. B·C의 사과 배경을 교정한 뒤 B의 봉인 상태, C의 주문서 한 장, D의 실물 사과 한 개·빈 주문서 0과 대사를 확인했다. 실제 조작·연출 검증은 미실행이다.

### 3.1 P02 시작값 — 화면·입력 승인 이력, 시간은 3.12절에서 후속 승인

2026-09-28 사용자가 3.2절의 시각 검토 도구를 제공받은 뒤 “승인”했다. **아래 화면·입력 시작값 한 묶음을 승인**한 것으로 기록하고 플레이 명세 v0.5의 1.2·3.3·4.1·Q18·D01에 반영했다. 시제품에 적용 후 검증할 시작값이며, 지원 기기·최종 그림 확정이나 실제 사용성 검증 완료를 뜻하지 않는다. 후속 P03·P04/P07·P05 승인 기록은 3.3·3.6·3.8절을 따른다. 아래 P02 승인 당시 일시정지 표시와 일반 버튼 설명은 이후 P05의 메뉴 표시로 변경했다. 연출 4종 시간과 힌트 3·6·10초는 이후 3.12절에서 확정했다. P06·P08은 이후 3.10·3.11절에서 승인했다.

**승인된 방향:** 화면 전체를 일괄 축소하지 않고, 글자·버튼·주문서 크기를 확보한 뒤 남는 공간에 장면을 배치한다. 상단은 장소·목표와 공통 버튼, 중앙은 등장인물·대상·마법진, 하단은 왼쪽 주문서와 오른쪽 대사로 구성한다. 현재 와이어프레임 이미지는 이전 장면 구성 참고로 유지하고, 현행 화면 배치는 플레이 명세 4.1절과 HTML 검토 도구를 따른다.

| 상단 | 왼쪽 장소·목표 각 한 줄, 오른쪽 도움·소리·일시정지 | 장소·목표 16px, 줄 높이 20px. 버튼 3개와 필수 정보가 겹치지 않게 배치 |
| 하단 주문서 | 왼쪽 고정 144×96px, 숫자 글자 크기 64px | 빈 0·사과 1·호박 1 모두 같은 크기. 배경 그림은 대표 물건 하나, 숫자 뒤 밝은 여백 유지 |
| 하단 대사 | 주문서 오른쪽, 간격 16px. 화자 16px, 본문 18px·줄 높이 26px·최대 두 줄 | 물건·마법진을 덮지 않는 별도 영역. 대사 진행 방식은 P04에서 결정 |
| 일반 버튼 | 입력 영역 최소 48×48px, 서로 8px 이상 간격 | 아이콘 그림 크기와 입력 영역을 구분. 도움·소리·일시정지·이동 등 공통 적용 |
| 주요 대상 입력 영역 | 주문서 144×96px, 마법진 최소 128×80px. 사과·호박은 각 가로·세로 72px 이상 확보 | 실제 그림의 형태·배치에 맞춘 경계와 보정은 T005에서 결정. 큰 호박의 보이는 몸체를 작은 일부 영역으로 제한하지 않음 |
| 화면 맞춤 | 화면 비율별로 장면을 재배치하고, 여유 공간은 배경과 대상 사이 간격에 사용 | 글자·입력 영역을 위 시작값보다 일괄 축소하지 않음. 주문서·대상·자막은 잘라내지 않음. 태블릿·PC의 확대 상한은 T005에서 결정 |

**640×320 배치 계산:** 세로 `56 + 8 + 144 + 8 + 104 = 320`. 하단 가로는 좌우 여백을 뺀 624px에서 주문서 144px·간격 16px를 빼면 대사 영역 464px다. 이는 공간 예산 계산이며, 실제 한글 줄바꿈·호박/용의 크기·손 시범·주문서 이동 경로가 들어맞는지는 화면으로 확인해야 한다.

- 기존 제안의 72px 버튼을 1280×720에서 640×360으로 일괄 축소하면 36px가 된다. 따라서 기존 논리 좌표 수치를 스마트폰 터치 크기로 그대로 채택하지 않는다.
- 입력 영역끼리 겹치지 않게 배치한다. 빈 배경 탭으로 선택을 취소하는 P09가 있으므로 보이지 않는 대상 영역을 과도하게 넓히지 않는다. 이전 드래그 판정 수치는 승계하지 않는다.
- 숫자·주문서·실물이 함께 보이는 원칙은 유지한다. 마법 중에는 하단 주문서 자리를 비우고 이동하는 한 장만 표시한다. 독립 실습·실전에서는 배치 편의를 이유로 정답 대상 강조를 추가하지 않는다.
- 16:9 고정 캔버스·전체화면 실행을 필수 조건으로 삼지 않는다. 주소창이 있는 상태와 없는 상태의 사용 가능 영역을 각각 확인한다. 세로 접속 시 안내·중단/복원, 기준보다 작은 화면 처리, OS·브라우저 범위는 미정이며 T005에서 별도 검토한다.

참고 근거: [W3C의 강화된 목표 크기 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)은 44×44 CSS px를 제시한다. 위 48px·72px 등은 이를 참고한 **프로젝트 검토값**이며 아동 사용성 보장이나 접근성 적합성 판정이 아니다. 브라우저 표시 영역·기기 여백의 기술 검토는 [MDN 뷰포트 단위](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)와 [안전 영역](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env)을 참조한다. 구현 수단·지원 버전은 아직 선택하지 않았다.

### 3.2 P02 시각 확인 도구 — 화면·입력 승인 기록

- 사용자 요청: “화면.입력시작값을 시각적으로 확인하여 승인여부를 판단할 수 있을까”.
- 파일: `P02_화면검토.html`(사용자 삭제). 별도 설치 없이 브라우저로 열 수 있는 수치 검토 도구다. 루트 와이어프레임 이미지는 유지하며, 비교 화면 캡처를 저장소에 추가하지 않는다.
- 조작: 화면 크기 5종·장면 8종 선택, 터치 영역·영역 높이 표시, 화면 맞춤·1:1 보기. 그림 속 대상을 누르면 입력 영역의 CSS 크기만 표시한다. 봉인·소환·힌트·음성·저장 등 제품 동작을 구현한 것이 아니다.
- 1:1은 브라우저 배율 100%에서 CSS 크기를 확인하는 방식이다. 화면 맞춤이 축소되면 배율을 표시한다. 모니터에서 보이는 물리 크기가 휴대폰과 같다는 뜻은 아니다.
- 장면: S02 봉인 전, S03 소환 전/중/후, S04 독립 실습, S07 호박 봉인 전, S09 소환 전/후. S09 소환 전의 대사는 비워 해결법을 추가하지 않았다. S03 안내 손 시범은 이 수치 검토 도구의 범위에 포함하지 않는다.
- 임시 자산: 단순 SVG 도형·색으로 대략적인 공간 점유를 보여준다. 사과 입력 영역 72×72, 호박 160×126, 교실 마법진 128×80, 큰 호박용 접시 192×80 CSS px로 시각화했다. 호박은 봉인 전·복원 후 동일한 그림 크기다. 최소 영역을 넘는 대상별 크기와 위치는 비교용이며 최종 입력 경계·캐릭터 디자인의 승인이 아니다.
- 브라우저 검사: Chromium 153.0.8010.53, 5개 크기×8개 장면 40개 조합. 상단 56·하단 104·본문 18·숫자 64px, 주문서 한 장, 대상 영역의 화면 내 배치, 활성 입력 영역끼리 겹침 없음, 대사 가로 넘침·두 줄 초과 없음 확인. 크기 전환·장면 전환·영역 표시·주문서 클릭 크기 표시·축소 배율 표시 확인, 스크립트 오류 없음.
- 직접 시각 확인: 640×320의 S04 터치 표시·S07, 800×360의 S03 전/중/후·S09 소환 후. 검사 중 버튼 크기 라벨의 기준 위치와 접시 크기·호박 위치를 교정했다. 중앙 장면 높이는 각각 144·184px이므로 실제 사용자가 느끼는 답답함은 검토가 필요하다.
- 남은 검증: 실제 스마트폰 터치, 지원 OS별 글꼴·줄바꿈, 브라우저 표시줄·안전 영역, 안내 손·움직이는 마법과 음성·힌트. 브라우저 검사 결과는 Q18 전체 통과를 뜻하지 않는다. P02 승인은 검사 결과와 별개인 사용자의 명시적 “승인”을 근거로 한다.
- 결정 결과: 화면·입력 시작값 승인·플레이 명세 v0.5 반영 완료. 후속 P03 결정은 3.3절 참조. 당시 미정이었던 P02 연출·힌트 시간은 이후 3.12절에서 확정했다.

### 3.3 P03 무거움 체험 — 단일 일반 연출 승인

확정안은 **준비실 입장 → 들기 실패 자동 연출 1회 → 바로 자율 조작**이다. 호박이 무거워 마법이 필요한 상황을 먼저 보여주되, 반복 실패나 특정 탭을 진행 조건으로 요구하지 않는다. 2026-09-28 사용자가 시각 검토·연출 설정 설명 후 “권장안대로 일반적인 방식으로 한가지 연출로 통일하고 필요성이 확인되면 추가하는 편이 적절”이라고 결정했다. 일반 연출 한 가지만 적용하며, 플레이 명세 v0.6의 5.3절·S06·D03에 반영했다.

| 단계 | 화면·진행 |
| --- | --- |
| 1. 준비실 도착 | 바닥에 큰 호박 한 개, 빈 주문서 0. 별도 ‘들기’ 버튼이나 호박 탭을 요구하지 않음 |
| 2. 실패 자동 연출 1회 | 주인공이 호박을 들어보려 하지만 들지 못함. 호박은 거의 움직이지 않고 바닥에 남음. “으으… 너무 무거워.” 대사. 상해·낙하 연출 없음 |
| 3. 자율 조작 시작 | 체험 완료 상태 CP06을 저장하고 S07로 진행. 호박 바깥·주문서 0 유지. 목표만 제시하고 바로 주문서→호박 탭으로 봉인 가능. 해결법·손 시범을 먼저 보여주지 않음 |

- 완료 후 반복 없음: 같은 플레이에서 CP06 또는 그 이후 체크포인트로 복원하면 들기 실패를 재생하지 않는다. 호박을 다시 탭해도 실패 동작을 반복하지 않는다.
- 단일 일반 연출: 첫 시제품은 짧고 차분한 연출 한 가지로 통일한다. 연출 감소 모드·학습자 연출 선택 설정은 제공하지 않고 필요성이 확인되면 추가 검토한다. 이전 두 모드 제안은 현행 기준에서 제외했다. 음소거·일시정지·자막은 유지한다.
- 중단·복원은 플레이 11.3절을 따른다. 일시정지·창 비활성 후에는 중단 지점에서 재개한다. CP06 완료 전 새로고침은 이전 완료 체크포인트로 돌아가므로 재진입 때 아직 완료하지 않은 체험이 다시 나올 수 있다. ‘완료 후 반복 없음’과 구분한다.
- 승인 범위는 단일 일반 연출의 자동 시작·1회 체험·즉시 자율 조작·완료 후 반복 방지다. **1.8초는 기존 제안값이며 이번 승인 대상에서 제외**한다. 검토 재생 약 4초, 봉인·소환·가벼움 시간과 힌트 간격도 별도 미정이다.
- 플레이 명세 1.3·4.2·5.3·S06·D03·Q07·Q17에 반영하고 CP06→S07·Q08·11.3절과 대조했다. P05 제안에서 연출 감소 항목만 제거했으며 설정 진입 방식 전체의 승인은 아니다. 제품 구현 착수 조건은 기존 T004·T005를 유지한다.
- 검토 결과: 기존 장면·저장·실전 즉시 봉인 규칙과 문서상 충돌 없음. 아래 독립 검토 도구도 단일 일반 연출로 갱신했다. 제품 앱의 자동 연출·중단 복원은 미검증이다.

### 3.4 P03 시각 확인 도구 — 승인된 단일 연출 반영

- 사용자 요청: “권장안을 시각화해서 승인을 판단할수 있게 해줄 수 있나”. 파일: `P03_무거움검토.html`(사용자 삭제). P02 화면·입력 시작값을 유지한 독립 검토 도구이며, 제품 앱 구현이나 기술 선택이 아니다. 기존 P02 파일과 루트 와이어프레임은 유지했다.
- 현재 조작: ‘처음 입장 재생’으로 일반 연출 한 가지를 확인한다. 다가가서 한 번 들어보지만 호박은 바닥에 남는다. 체험 뒤에는 대사를 비우고 목표만 남기며 입력을 바로 허용한다. 정지 장면 카드 3개로 각 상태를 다시 확인할 수 있다. 연출 선택 메뉴·감소 모드·OS 설정에 따른 두 모드 분기를 제거했다.
- ‘완료 후 재진입 비교’는 CP06 완료 상태를 불러온 경우만 모사하며, 들기 실패 없이 자율 조작을 보여준다. 저장소 접근·실제 체크포인트 저장·재접속 복구는 없다. 페이지를 새로 열거나 새로고침하면 검토 첫 화면으로 돌아온다. 제품의 완료 전 새로고침 규칙은 3.3절·플레이 11.3절을 따른다.
- 자율 조작 확인: 호박 단독 탭으로 실패를 반복하지 않음, 주문서 선택·재탭/배경 탭 취소, 선택 직후 호박 탭 수신을 확인한다. 주문서→호박 뒤에는 검토자 영역에 입력 확인만 표시하고 봉인·이동은 실행하지 않는다. 호박 한 개·주문서 0을 유지한다. 도움·무음 아이콘은 배치 참고이며 음성·힌트는 포함하지 않는다.
- 시간·그림: 전체 검토 재생 약 4초는 포즈 비교를 위한 임시 속도다. **1.8초 등 실제 연출 시간 승인과 무관**하며, 그림·캐릭터·포즈도 임시다. 화면 크기 640×320·800×360·960×720, 화면 맞춤·1:1 비교를 제공한다. 화면 맞춤의 축소는 검토자 미리보기이며 제품의 화면 맞춤 구현이 아니다.
- 이전 검증 이력: 두 모드 제안 당시 Windows·Chromium 153.0.8010.53에서 18개 화면 조합과 두 모드의 재생·일시정지·입력·재진입 모사 검사를 통과하고 대표 6개 상태를 직접 확인했다. 현재 단일 연출 수정 후 검증 결과는 TASKS에 별도 기록한다. 창 비활성 처리기는 합성 visibilitychange 이벤트로만 검사했으며 실제 OS 전환 시험이 아니다.
- 남은 검증: 제품 앱·실제 스마트폰/태블릿 터치·OS 창 비활성·음성·실제 저장/복구·전체 Q01–Q20. P03 승인은 검사 통과가 아니라 사용자의 명시적 단일 연출 결정을 근거로 한다. 소스는 저장소, 일회성 검사 스크립트·캡처는 저장소 밖에 둔다.

### 3.5 P04 대사 진행 — 이전 음성 포함 초안, MVP 미채택

아래는 **음성·자막 자동 진행과 선택적 대사 넘김**을 제안했던 이력이다. 이후 사용자가 3.6절의 대사 음성 없는 MVP·자막 다음 진행을 승인했으므로 아래 초안은 MVP에 적용하지 않는다. 고도화 TTS 추가 시 자동 진행을 채택한 것으로도 취급하지 않는다. 현행 제품 기준은 플레이 4.4절이다.

| 상황 | 당시 제안 동작 — MVP 미채택 |
| --- | --- |
| 이야기·설명 대사 | 하단에 한 문장의 자막을 한 번에 표시하고 같은 내용의 음성을 재생. 정상 재생이 끝나면 다음 문장으로 자동 진행 |
| ‘다음’ 누르기 | 현재 음성을 중단하고 현재 문장만 종료. 다음 문장이 있으면 표시·재생하고, 마지막 문장이면 해당 설명을 마침. 한 번의 탭이 여러 문장을 넘기거나 물건 입력으로 동시에 처리되지 않음 |
| 무음 | 같은 자막을 유지하고 해당 음성의 재생 길이만큼 표시한 뒤 자동 진행. ‘다음’도 사용 가능. 소리만 바꾸며 별도 대사 진행 모드를 만들지 않음 |
| 음성 재생 실패·누락 | 문장별로 준비한 대체 표시 시간을 사용해 자막으로 계속 진행. 음성 성공을 기다리며 멈추지 않음. 실제 길이·대체 시간·재생 중 멈춤 판정은 음성 자산/구현 검토 때 정함 |
| 실습·이동 대기 | 설명이 끝나도 필요한 주문서 펼치기·봉인·소환·이동 표식 탭은 직접 수행해야 함. ‘다음’은 수행 완료나 체크포인트를 대신 만들지 않음 |
| 일시정지·창 비활성 | 기존 3.4·11.3절대로 음성·자막 진행 시간을 함께 멈추고 같은 지점에서 재개. 음소거 전환은 현재 문장을 처음부터 재시작하거나 즉시 종료시키지 않음 |

**구체적 예 — S05 첫 심부름:** “이제 이 주문서는 네 것이란다.” → “온실의 용에게 간식을 가져다주겠니?” → “준비실에 있는 호박 하나를 가져가면 된단다.”를 차례로 재생한다. 기다리면 자동으로 이어지고, ‘다음’은 현재 문장만 넘긴다. 대사가 끝난 뒤에도 준비실로 이동하려면 기존 명세대로 이동 표식을 눌러야 한다. 대사만으로 자동 이동하거나 호박 봉인을 완료하지 않는다.

**기존 승인 규칙과의 경계:**

- 주문서 선택·오조작 안내는 P09의 짧은 상태 안내다. ‘다음’을 누르거나 음성이 끝날 때까지 기다릴 필요 없이 바로 올바른 대상 입력을 받을 수 있다. 새 상태 안내가 시작되면 이전 음성을 중단한다.
- S06 무거움, S08 가벼움, 봉인·소환 등에 붙은 짧은 대사는 해당 연출과 함께 처리한다. 이 구간에는 별도 대사 ‘다음’ 버튼·추가 대사 대기를 두지 않고 기존 완료 조건을 유지한다. P03의 자동 실패 1회→즉시 자율 조작을 바꾸지 않는다.
- S02·S03의 필수 조작 안내·손 시범과 실제 실습은 대사 넘김으로 완료 처리하지 않는다. S04·S07·S09는 기존 자율 조작과 단계별 도움을 유지하며 정답 안내를 미리 추가하지 않는다.
- S00의 ‘도입 넘기기’는 S01까지만 이동하는 기존 별도 동작이다. 문장별 ‘다음’과 구분한다. S10은 기존 ‘다시 하기·종료만 제공’ 규칙을 유지하며 별도 ‘다음’을 추가하지 않는다.

**버튼 배치 검토안:** 이야기·설명 대사 구간에만 하단 대사 영역 오른쪽에 ‘다음’ 화살표를 둔다. P02의 일반 버튼 최소 48×48px·간격 8px를 적용하면 640px 화면에서 대사 너비는 `464 - 48 - 8 = 408px`다. 글자 크기·하단 높이를 줄이지 않는다. 버튼이 없을 때는 원래 대사 너비를 사용한다. 실제 문장별 두 줄 이내 배치·버튼 식별은 시각 검토가 필요하며, 긴 문장은 뜻을 유지한 분할안을 별도 확인한다. 버튼 위치·분할 문구는 아직 확정하지 않는다.

**당시 승인 요청 범위(미채택):** 자동 진행을 기본으로 하는 흐름, 선택적 ‘다음’, 무음/음성 오류 시 대체 시간. 현재 승인 사항과 구분하며, 위 시간 기반 진행을 MVP에 구현하지 않는다. 최종 버튼 배치·긴 문장 분할은 현행 자막 방식에 맞춰 다시 검토한다.

**당시 검토 결과:** 승인된 장면·입력 규칙과 문서 대조만 수행했다. 음성·자막·다음 버튼 실제 동작, 작은 화면 렌더링, 터치·기기 시험은 미실행이었다. 현재 결정과 다음 작업은 3.6절·TASKS를 따른다.

### 3.6 MVP 대사 음성 제외·후속 TTS — 승인(P04/P07)

**승인 근거:** 사용자 “음성은 고도화때 tts…MVP에서는 음성은 무음…검토하라”에 대해 아래 검토 결과를 제시했고, 2026-09-28 “승인”을 받았다. ‘무음 MVP’는 **대사·상태 안내·힌트의 사람 목소리를 탑재하지 않는 것**이다. 효과음·배경음까지 없애는 결정은 포함하지 않는다.

**확정 범위:** 첫 MVP는 조작·물건/숫자 상태·장면 연결·저장/복구 검증을 우선한다. 음성 제작·검수·재생 처리는 고도화 단계로 미룬다. 최종 대상은 글 읽기가 어려운 숫자 입문 아동을 포함하되, MVP 기능 통과를 이들의 독립 플레이·학습 효과 검증과 동일하게 취급하지 않는다. 현행 기준은 플레이 v0.7의 1.2·4.4·13절이다.

| 항목 | 승인된 MVP 범위 | 고도화 단계 |
| --- | --- | --- |
| 대사·상태 안내·힌트 | 음성 파일·TTS 호출 없이 자막과 기존 시각 안내로 표시 | 확정 대사로 한국어 TTS를 제작·연결하고 발음·속도·문장 전환을 확인 |
| 이야기·설명 대사 진행(P04) | 자막 한 문장을 표시하고 ‘다음’을 누를 때 진행. 읽기 전에 사라지지 않도록 자동 넘김은 보류. 자동/수동 선택 설정은 만들지 않음 | 음성 종료에 맞춘 자동 진행과 대사 넘김의 필요성을 다시 검토. 기존 3.5절을 자동 승인하지 않음 |
| 짧은 반응·조작 안내 | P03 무거움 반응은 기존 연출과 함께 끝냄. P09 선택·오조작 안내는 다음 입력을 막지 않음. 모든 자막에 ‘다음’ 대기를 붙이지 않음 | 음성을 추가해도 승인된 즉시 입력·상태 갱신·필수 수행 조건 유지 |
| 시각 안내 | S02·S03의 기존 손 시범·그림·0/1 변화를 유지. S04·S07·S09의 자율 시도·단계별 도움 순서를 유지 | 음성 유무에 따른 이해·사용성 차이를 실제 대상 아동에게 확인 |
| 음향·버튼 | 대사 음성 제외와 효과음 제외를 구분. 효과음을 사용할 수 있으므로 소리·음소거 버튼을 이 결정만으로 제거하지 않음 | 실제 음향 범위에 맞춰 소리 제어를 결정 |
| 검증·관찰 | 기능·흐름 검증 중심. 진행자가 대사를 읽거나 설명해 주면 외부 도움으로 기록하고 독립 수행과 구분 | 읽기가 어려운 아동의 독립적인 목표 이해·실전 활용을 음성 포함 상태에서 검토 |

**P04 수정 범위:** 이야기·설명 자막은 학습자의 ‘다음’ 입력으로 넘기되, S00 도입 넘기기·S10 다시 하기/종료·S06/S08 필수 연출에는 기존 규칙을 유지한다. S10 마무리 자막의 유지/분할 방식은 별도 화면 검토 대상으로 남기며, 음성 길이에 의존하는 자동 종료를 그대로 적용하지 않는다. 대사 넘김은 주문서 펼치기·봉인·소환·이동 표식 탭을 대신하지 않는다. 버튼의 최종 배치·긴 문장 분할은 여전히 미정이다.

**후속 TTS를 위한 준비 권장:** 대사 문구를 장면 동작 코드와 분리하고, 같은 대사에 나중에 음성을 연결할 수 있도록 식별 기준을 둔다. MVP 진행은 음성 파일이나 재생 성공을 필수로 요구하지 않는다. 지금 TTS 서비스를 연동하거나 음성 오류 처리 전체를 미리 구현하지 않는다. 기술·데이터 구조·파일 생성/실시간 합성·TTS 서비스는 T005 및 고도화 시 별도 결정한다.

**반영 완료:** 플레이 v0.7의 MVP 검증 범위·상태 안내·4.4 자막 진행, S01/S05/S07/S10, Q13/Q17/Q18, 관찰·자산; 검토안 P04/P07·P05 음향 범위 설명; 개발 명세의 후속 TTS 준비·검증 범위; TASKS T009/T011/T012. 다른 승인 규칙은 유지한다.

**당시 상태:** P04/P07 승인·명세 반영 완료. 검토 HTML·제품 코드는 이번 승인 반영에서 변경하지 않았다. TTS 서비스 조사·설치·제작·청취와 실제 아동 사용 시험은 미실행이다. 다음은 P05 설정 진입이며, 버튼 배치·문장 분할·S10 마무리 자막·효과음·TTS 도구는 별도 미정이다.

### 3.8 P05 일시정지의 필요성 재검토 — 메뉴 진입 승인

아래는 v0.8 승인 이력이다. 메뉴의 소리 항목은 이후 3.9절 승인으로 제거했으며, 현재 구성은 돌아가기·그만하기다.

2026-09-28 사용자 “실시간 게임이 아닌 현재 상태에서 일시정지는 어떤의미가 있을까? … 검토하라”에 따른 검토다. **안정 상태에서 입력을 기다리는 동안은 별도 정지 없이도 물건·숫자·장면이 유지된다.** 시간제한·생존·실시간 점수 경쟁이 없고 설명 자막도 다음 입력을 기다리므로, 학습자에게 일시정지를 주요 기능으로 강조할 이유는 약하다.

| 구간 | 아무 입력 없이 기다림 | 내부 진행을 멈춤 |
| --- | --- | --- |
| 설명 자막·안정 상태 | 다음 입력 전까지 자막·물건·숫자·진행 유지 | 진행 측면에서 차이 거의 없음. 창을 열면 뒤쪽 입력은 차단 |
| 조작 가능 상태의 자동 도움 | 시간이 지나면 도움 단계가 올라갈 수 있음. 구체적 시간값은 미정 | 자리를 비운 동안 힌트가 진행되거나 불필요한 도움 단계가 기록되는 것을 방지 |
| 봉인·소환·이동·무거움 등의 짧은 연출 | 시작된 동작은 끝까지 진행 | 현재 위치에서 멈춰 돌아왔을 때 이어 볼 수 있음 |

현재 P05 HTML은 자동 도움·실제 연출을 구현하지 않았다. 이전 시안에 표시한 경과 시간은 정지 처리를 확인하기 위한 검토용 수치였으며, 제품이 시간제 게임이거나 일시정지 버튼이 필수라는 근거가 아니다. 기존 시안은 일시정지 역할을 필요 이상으로 강조했다.

**승인된 수정안:** 상단 ‘Ⅱ 일시정지’를 ‘메뉴’ 진입으로 대체하고 창 제목도 ‘메뉴’로 표시한다. 메뉴 안에는 돌아가기·소리·그만하기를 둔다. 학습자가 쉴 때 꼭 버튼을 눌러야 한다고 안내하지 않는다. 메뉴를 열었을 때와 창이 비활성일 때의 내부 연출·힌트 정지, 선택 유지·배경 입력 차단은 보존한다. 기존 상단 도움·소리까지 함께 제거하는 안은 아니다.

**승인 근거·반영:** 사용자가 위 수정 권장안에 “승인”했다. 2026-09-28 플레이 v0.8의 4.1·4.5·11.3·Q15/Q16 및 관련 조작 설명, P05 HTML·개발 명세·TASKS에 반영했다. 자동 힌트 폐지나 연출 중단 원칙 제거는 아니다. P05 HTML은 메뉴 기호·제목·돌아가기 표시로 갱신하고 검토용 경과 시간의 화면 노출을 제거했다. P02/P03 HTML·루트 와이어프레임은 이전 화면 참고로 보존한다. 종료 동작은 P06, 음향 범위·기본 소리·설정 보관은 별도 결정한다. 제품 앱·실제 기기 검증·커밋·푸시는 미수행이다.

**승인 반영 검증:** Chromium 153.0.8010.53에서 기존 9개 화면 조합·상태 보존·입력 차단·소리 동기·키보드·합성 창 비활성·맞춤 검사 재통과, 스크립트 오류 0. 전체 화면과 640×320 메뉴 화면 직접 확인. 실제 기기·제품 앱·음향·종료/저장은 미검증.

### 3.9 P05 소리 단추 중복 검토 — 상단만 유지 승인

2026-09-28 사용자 “소리 온오프 단추가 있는데 메뉴에도 또 넣는 것은 중복같다. 검토하라”에 따른 검토다. 검토 당시 플레이 v0.8 4.5절과 P05 HTML에서 상단·메뉴 단추는 동일한 소리 상태를 바꾸는 같은 기능이다. 대사/효과음 등 서로 다른 소리 종류를 제어하지 않는다. 당시 HTML에서도 두 단추가 같은 `toggleSound` 처리를 사용했다.

두 곳에 두면 메뉴를 연 채 소리를 바꿀 수 있지만, 현재 MVP에서 별도 기능으로 오인할 여지가 있고 제어 항목만 늘어난다. 이 이점만으로 중복을 유지할 필요는 낮다.

**승인안:** 소리 켜기/끄기는 상단 한 곳에만 남기고 메뉴의 소리 항목을 제거한다. 메뉴는 돌아가기·그만하기 두 항목으로 구성한다. 메뉴를 거치지 않고 한 번에 소리를 바꿀 수 있고, 기존 상단 배치를 유지하면서 중복만 줄일 수 있다. 메뉴 안에서는 돌아간 뒤 상단 소리를 눌러야 하는 차이가 있다. 메뉴에만 소리를 남기는 대안도 가능하지만, 현재 승인 배치에서의 최소 변경과 즉시 음소거를 우선해 상단 유지를 권장한다.

소리 제어 위치를 한 곳으로 모으는 제안이며 음향 자체를 제외하는 결정은 아니다. 효과음/배경음 범위·기본 소리·설정 보관은 별도 미정이다. 메뉴의 내부 정지·선택 보존·배경 입력 차단은 유지한다. 사용자가 이 부분 변경에 “승인”했다. 플레이 v0.9의 4.5절·Q15·P05 HTML·개발 검증 절차·TASKS에 반영했다. 메뉴 음향 제어·중복 상태 표시·연결 코드를 제거했으며 메뉴의 두 항목·상단 소리 전환·상태 보존을 확인한다. 기존 3.8절의 세 항목 구성과 소리 동기 검증은 당시 승인 이력이다. 루트 이미지·P02/P03 HTML은 유지한다.

**반영 후 검증:** Windows·Chromium 153.0.8010.53에서 9개 화면 조합, 메뉴 두 항목·소리 단추 한 개·상단 켜기/끄기·메뉴 복귀 후 상태 보존·입력 차단·키보드·합성 창 비활성·맞춤 검사 통과, 스크립트 오류 0. 전체 화면과 640×320 메뉴 직접 확인. 실제 기기·제품 음향·종료/저장은 미검증.

당시 반영 범위: 플레이 명세 v0.3의 3절, 11절, Q02·Q03·Q05·Q12·Q13·Q15·Q16, 14절 조작 안내 자산, 15.2절 D02. 이후 P02·P03·P04/P07을 별도 승인했다. P09의 즉시 입력·선택·취소는 유지하고 MVP 음성만 제외했다. P05 메뉴 진입은 추가 승인했다. 현재 결정 대기는 음향 세부사항과 기록 보관/구현 상세이며 실제 앱 동작 검증은 미실행이다.
