### 3.1 실행 형태 결정

- 결정: 첫 시제품은 스마트폰 가로 브라우저를 우선 기준으로 하는 웹 방식으로 진행하며, 태블릿 가로·PC도 지원한다. 스마트폰·태블릿 터치와 PC 마우스로 같은 플레이를 수행한다.
- 근거: 2026-09-28 사용자 지시 “웹방식으로 진행” 및 “스마트폰 가로를 우선하고 태블릿.pc도 지원하는 방향임”. 제품 범위는 플레이 명세서 C08·D01을 따른다.
- 추가 승인: 2026-09-28 사용자가 P02 시각 검토 도구 제공 후 화면·입력 시작값을 승인했다. CSS 표시 크기·화면 배분·맞춤의 제품 기준은 플레이 명세 v0.5의 1.2·3.3·4.1절을 따른다.
- 남은 결정: 지원 OS·브라우저와 버전, 최소 지원 화면·더 작은 화면 처리, 대상별 최종 입력 경계·보정, 태블릿/PC 확대 상한, 엔진·프레임워크, 실행·빌드 도구, 호스팅·접속 주소. T005에서 구체화한다.
- 640×320 CSS px는 작은 화면 검토 기준이며 최소 지원 크기 확정이 아니다. 기존 1280×720을 고정 축소 기준으로 채택하지 않는다. 내부 렌더링 좌표·화면 맞춤 구현·기기 안전 여백·세로 접속 시 처리는 T005에서 명시한다. 스마트폰 세로 플레이는 현재 제품 범위에 포함하지 않는다.
- 웹 방식 확정은 개발 환경 구성이나 실제 실행 검증 완료를 의미하지 않는다.

### 3.2 T005 기술·구현 계획 검토

2026-09-29 [기술·구현 계획안](기술_구현_계획안.md)을 작성했다. TypeScript·Vite·HTML/CSS·SVG, 단일 게임 상태, IndexedDB, Vitest·Playwright 및 실제 기기 검증을 권장한다. **아직 기술 선택 승인은 아니며 3절 표의 미정 상태를 유지한다.** 이번 검토는 기술 구성·설계 방향·구현 순서이고, 지원 화면·초기 소리 버튼·기록 보관/접근 상세는 계획안 5절에서 구분해 후속 검토한다.

현재 PC의 Node 22.21.1·npm 10.9.4는 환경 조회 결과다. 권장 Node 24 LTS로 전환하거나 패키지를 설치하지 않았다. 정확한 호환 버전은 T005 마무리에서 선정하고 T006에서 고정·실행 검증한다.

## 4. 코드 구조와 구현 설계

현재 코드 구조는 미정이다. 기술 선택 후 장면, 입력, 상태, 연출, 힌트, 저장·복구, 자산을 코드에서 어떻게 구성할지 기록한다.

플레이 명세서 11절을 기준으로 대상의 동일성, 상태 갱신, 중복 입력 방지, 중단·복구를 어떤 코드로 보장할지 구체화한다. 문서에 제안된 데이터 필드를 이미 구현된 구조로 간주하지 않는다.

### 4.1 MVP 대사와 후속 TTS의 구현 범위

2026-09-28 P04/P07 승인에 따라 플레이 명세 v0.7의 1.2·4.4·13·14절을 따른다.

- MVP에는 대사·상태 안내·힌트 음성 파일과 TTS 호출을 넣지 않는다. 음성 파일을 포함한 뒤 기본 음소거로 감추는 방식이 아니다. 전체 진행은 음성 재생 성공·종료·길이와 무관하게 작동해야 한다.
- 이야기·설명 자막은 ‘다음’ 입력으로 진행한다. 상태 안내·짧은 반응·S10 등의 예외와 필수 수행 조건은 플레이 4.4절을 따른다. 음성 재생·자막 동기·음성 오류 처리 체계는 MVP 필수 구현에서 제외한다.
- 대사 문구를 장면 동작과 분리해 후속 음성을 같은 대사에 연결할 수 있게 준비한다. 식별자·파일 형식·데이터 구조의 구체안은 T005에서 결정하며 지금 코드 구조를 확정하지 않는다.
- TTS는 고도화 단계에서 추가한다. 서비스·라이브러리·사전 파일 생성/실시간 합성·음성 검수 절차·후속 자동 진행 여부는 그때 검토한다. MVP를 위해 TTS 서비스 가입·키 설정·패키지 설치를 선행하지 않는다.
- 효과음·배경음 제작 범위는 대사 음성 제외와 별도 결정한다. 이 승인만으로 기존 소리·음소거 제어를 삭제하지 않는다.

2026-09-29 사용자 제안 및 후속 진행 지시에 따라, 효과음·배경음·소리 설정 검토는 핵심 기능 구현·검증 뒤로 이동했다(플레이 v0.15). T004의 음향 결정을 T005/T006 또는 T009 핵심/T010의 착수 조건으로 삼지 않는다. 음향 연결 전 버튼 표시 정책은 별도 제품 검토 사항이다. 음향이 진행·저장 성공의 전제 조건이 되지 않도록 구성한다.

### 4.2 수행·관찰 기록의 구현 범위 — P08 승인

2026-09-29 사용자 승인에 따라 제품 기준은 플레이 v0.11의 S10·11.3·13.2절, 검증 기준은 12.1절을 따른다.

- 익명 세션별 로컬 기록·개발/관찰용 열람·JSON 수동 내보내기·확인 후 관찰 기록 삭제는 승인된 기능 범위다. 학습자 화면에 기록/평가 UI를 추가하거나 외부 자동 전송을 붙이지 않는다.
- 자동 수행·도움 기록과 관찰자의 외부 도움·설명 입력을 구분한다. H0와 외부 도움 미확인을 독립 수행 판정으로 바꾸지 않는다.
- 플레이 체크포인트와 관찰 기록의 보관·삭제 경계를 구분한다. 이어하기의 세션 유지·다시 하기의 새 세션·재접속 중복 방지·삭제한 과거 기록 복구 방지를 설계한다.
- T005에서 저장 수단·데이터 구조·갱신/실패 처리, 보관 기간·상한·용량 초과 처리, 내보내기 세부 형식·개발용 접근 방법을 구체화한다. 보관 기간/상한은 아직 미정이며 무제한 또는 자동 삭제로 임의 확정하지 않는다.
- 현재 구현·패키지 설치·기록 수집·내보내기·삭제 시험은 미착수다. 새 검토용 HTML 없이 승인 문서와 예시를 기준으로 인계한다.

### 5.2 집·회사 간 작업 전달

1. 보내는 PC에서 관련 명세와 `TASKS.md`를 갱신하고 Git 변경·미등록 파일을 확인한다.
2. 사용자 지시에 따라 커밋할 때에는 인계에 필요한 문서·코드·자산·잠금 파일을 포함하고 비밀정보·일회성 파일은 제외한다. 커밋과 원격 반영의 수행 여부를 구분해 보고한다. 미커밋 파일은 Git으로 자동 전달되지 않는다.
3. 받는 PC에서는 먼저 로컬 변경과 브랜치를 확인한다. 기존 작업을 보존한 상태에서 전달된 변경을 가져오고, 전달받은 커밋과 필요한 파일이 있는지 확인한다. 원격에 접근하지 못했다면 최신 여부를 미확인으로 기록한다.
4. `AGENTS.md`의 새 세션 시작 절차를 따른다. 실행 프로젝트가 구성된 뒤에는 5절의 도구 버전·설치·실행·검증 절차로 환경을 재현하고 결과를 기록한다.

현재는 코드·패키지 구성이 없어 앱 환경 재현은 미실행이다. 문서 인계 규칙의 완료와 다른 PC에서의 앱 실행 성공을 구분한다.
